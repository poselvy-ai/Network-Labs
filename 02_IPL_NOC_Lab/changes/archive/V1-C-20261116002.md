# C-20261116002 — Replace DMZ-SRV1 IOL stand-in with Ubuntu web server

| Field | Value |
|-------|-------|
| Type | **Normal** |
| Requester | Patrick O. Selvy |
| Related ticket | [TICKET-002](../../tickets/archive/V1-TICKET-002.md) (P3) |
| CIs affected | DMZ-SRV1 (172.16.50.10, public 198.51.100.10); FW1 ARP entry for 172.16.50.10 |
| Window | 2026-11-16 17:00–18:00 PST |
| Status | **Superseded.** Built into the v2 baseline (lab rebuilt from scratch 2026-11-16) instead of being applied to the v1 lab |

## Reason

DMZ-SRV1's HTTP service (TCP/80) refuses all connections (TICKET-002). The network path is proven good. DMZ-SRV1 is an IOL router acting as a server, and its built-in HTTP service is not a real web server. Replacing it with an Ubuntu server running a real web service makes the DMZ behave like production and resolves TICKET-002.

The new server is managed like a production Linux server: systemd service, host firewall (ufw), SSH admin access restricted to internal management networks.

## Design

| Item | Value |
|------|-------|
| OS | Ubuntu (CML "Ubuntu" node) |
| IP / gateway | 172.16.50.10/24, default route via 172.16.50.1 (FW1 dmz) |
| Web service | `ipl-web.service` (systemd), TCP/80. Python's built-in web server: the lab has no internet access to install nginx/Apache |
| Host firewall (ufw) | Deny inbound by default; allow TCP/80 from any; allow SSH (TCP/22) only from 10.0.0.0/16 (core/HQ) |
| Admin account | `srvadmin` (sudo). Lab password set by cloud-init; changed at first login |
| Build file | [`../configs/DMZ-SRV1-cloud-init.yaml`](../../configs/DMZ-SRV1-cloud-init.yaml) |

No firewall policy change is needed: inside → dmz is allowed by security level, and outside → dmz TCP/80 is already permitted by `OUTSIDE-IN` to 172.16.50.10.

## Risk and impact

- **Low.** DMZ-SRV1 is already down for HTTP; no working service is interrupted.
- New MAC address behind the same IP: FW1 may hold the old ARP entry. Mitigated by clearing ARP on FW1 (step 6).
- Ubuntu node uses more RAM than IOL (about 2 GB); host has headroom.

## Implementation plan

1. **Record the before state.** On DMZ-SRV1 (IOL): `show running-config` → saved as [`../configs/DMZ-SRV1-IOL-legacy.txt`](../../configs/DMZ-SRV1-IOL-legacy.txt).
2. **Stop and remove the old node.** In CML: DMZ-SRV1 → Stop → Wipe → Delete.
3. **Add the new node.** Drag an **Ubuntu** node onto the canvas, name it `DMZ-SRV1`.
4. **Cable it.** Ubuntu's first interface → **FW1 GigabitEthernet0/3** (dmz).
5. **Apply the build.** DMZ-SRV1 → Config tab → replace the contents with `DMZ-SRV1-cloud-init.yaml` → Save. Start the node and wait about 2 minutes for cloud-init to finish.
6. **Refresh FW1's ARP.** On FW1: `clear arp`.

## Test plan

| Command | Expected |
|---------|----------|
| `cloud-init status` | `status: done` |
| `ip -br addr` | 172.16.50.10/24 on the `en*` interface, UP |

| `ss -tlnp \| grep :80` | python3 listening on `0.0.0.0:80` |
| `sudo ufw status verbose` | Default deny incoming; 80/tcp ALLOW Anywhere; 22/tcp ALLOW 10.0.0.0/16 |
| `curl -s localhost` | The IPL portal HTML |

From the network:

| From | Command | Expected |
|------|---------|----------|

| SCADA-PC1 | `ping 172.16.50.10` | 5/5 |
| SCADA-PC1 | `telnet 172.16.50.10 80`, then type `GET / HTTP/1.0` and press Enter twice | `HTTP/1.0 200 OK` and the portal HTML |

## Backout plan

1. Stop, wipe and delete the Ubuntu DMZ-SRV1.
2. Add an IOL node named DMZ-SRV1, cable it to FW1 Gi0/3, paste [`../configs/DMZ-SRV1-IOL-legacy.txt`](../../configs/DMZ-SRV1-IOL-legacy.txt) into its Config tab, start it.
3. On FW1: `clear arp`. Verify `ping 172.16.50.10` from SCADA-PC1.

## Result

Not implemented on the v1 lab. The design (Ubuntu DMZ-SRV1, cloud-init build, ufw, restricted SSH) was carried into the v2 baseline `configs/IPL-NOC-Baseline.yaml`. Verification of the new server is part of the v2 baseline checks.
